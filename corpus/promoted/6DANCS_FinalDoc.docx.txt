Project Title:  CUSTOMER SUPPORT ASSISTANT (NLP + RL) 
 
 
Project Description 
This project builds a Customer Support Assistant for the e-commerce domain, combining Natural Language Processing (NLP) and 
Reinforcement Learning (RL) to automatically classify customer intent and select appropriate responses. The dataset used is the 
Bitext Customer Support LLM Chatbot Training Dataset, a publicly available, synthetically generated benchmark sourced from 
HuggingFace (Bitext, 2023). It contains 27,000 labeled customer support utterances across 27 e-commerce intent categories such as 
tracking orders, requesting refunds, cancelling orders, and handling payment issues. 
The system uses DistilBERT-base-uncased as the core NLP model for intent classification, an epsilon-greedy contextual bandit 
(LinUCB) as the RL component for response selection, and a TextCNN as a supporting CNN experiment and comparison baseline. The 
dataset was preprocessed, split, and used to train and evaluate all three components. This project serves as an academic prototype 
demonstrating end-to-end AI system design for customer support automation. 
 
 
Project Objectives 
•       To design a DistilBERT-based intent classification model capable of categorizing e-commerce customer support messages 
into 27 intent classes, achieving a macro-F1 score of at least 0.85 on the held-out test set. 
•       To implement a TextCNN as a supporting CNN experiment for intent classification using GloVe word embeddings, with 
ablation studies across embedding modes (static vs. fine-tuned) and filter size configurations ([2,3,4] and [3,4,5]), to serve as 
a comparative DL baseline against DistilBERT. 
•       To evaluate an epsilon-greedy contextual bandit (LinUCB) for automated response selection, ensuring that the RL agent 
achieves a task success rate of at least 70% and demonstrates a measurable improvement in cumulative reward over a 
random response baseline. 
 
 
Data Preparation 
The dataset was sourced from HuggingFace as the Bitext Customer Support LLM Chatbot Training Dataset (Bitext, 2023), available 
under a Creative Commons Attribution 4.0 International (CC BY 4.0) license. It is synthetically generated and contains no personally 
identifiable information (PII). The raw file contained the columns instruction and intent, which were renamed to text and intent 
respectively during loading. All preprocessing steps were implemented in data/get_data.py and are described below. 
The following preprocessing steps were applied in sequence: 
•       Column selection and renaming: Only the instruction and intent columns were retained from the raw CSV. The 
instruction column was renamed to text and the intent column was kept as-is. 
•       Null removal: Rows with any null values were dropped using dropna(). 
•       Text normalization: All text was converted to lowercase and stripped of leading/trailing whitespace. Extra internal 
whitespace was collapsed using regex (\s+). Only alphanumeric characters and select punctuation (?, !) were retained; all 
other special characters were removed. 
•       Intent normalization: Intent labels were cast to string, converted to lowercase, and stripped of whitespace to ensure 
consistency across labels.

•       Duplicate removal: Exact duplicate rows based on the (text, intent) pair were removed after cleaning. 
•       Length filtering: A word count column was computed for each utterance. Rows with zero words (empty text) were 
removed. Rows exceeding 128 words were also removed, though in practice no utterances exceeded 16 words. 
•       Rare intent removal: Intents with only a single sample were removed to ensure stratified splitting was possible, though 
all 27 intents in this dataset had sufficient samples. 
•       Train/Validation/Test split: An 80/10/10 stratified split was applied using train_test_split() from scikit-learn with 
random_state=42. The stratify parameter ensured proportional representation of all 27 intent classes across splits.

The cleaned dataset contains 24,185 utterances across 27 e-commerce intent categories. Each record consists of a customer support 
message (text) and its corresponding intent label. The dataset is synthetically generated, meaning all utterances were 
programmatically created to simulate real customer support language across a range of e-commerce scenarios.

Training Process 
Non-DL Baseline: TF-IDF + Logistic Regression As the non-deep learning baseline, a Term Frequency-Inverse Document Frequency 
(TF-IDF) vectorizer was applied to transform raw text utterances into numerical feature vectors. TF-IDF works by assigning higher 
weights to words that appear frequently in a specific document but rarely across the entire corpus, making it effective at capturing 
discriminative vocabulary for each intent class. The vectorizer was configured with a bigram range (ngram_range=(1,2)), meaning it 
captures both individual words and two-word phrase combinations as features, and was limited to a maximum vocabulary of 10,000 
features to control dimensionality. The resulting TF-IDF vectors were then passed to a Logistic Regression classifier configured with a 
regularization strength of C=5.0, a maximum of 1,000 solver iterations, and a fixed random seed of 42 for reproducibility. Logistic 
Regression was chosen as the non-DL baseline because it is interpretable, computationally inexpensive, and well-established as a 
strong text classification baseline in NLP literature. Both the vectorizer and classifier were fitted exclusively on the training split, and 
the fitted vectorizer was applied to transform the test split without refitting, ensuring no data leakage.

DL Baseline: DistilBERT (NLP Core Model)  
The core NLP model is DistilBERT-base-uncased, a distilled version of BERT. DistilBERT retains approximately 97% of BERT's language 
understanding capability while being 40% smaller and 60% faster to run, making it well-suited for academic prototypes with runtime 
constraints. Unlike TF-IDF which treats words as isolated features, DistilBERT produces deep bidirectional contextual representations 
meaning the embedding of each token is influenced by all other tokens in the sentence, allowing the model to capture nuanced 
semantic relationships. The model was fine-tuned on the project's training split using the HuggingFace Transformers Trainer API. 
Fine-tuning involves taking the pre-trained DistilBERT weights and continuing to train them on the task-specific dataset, updating the 
model parameters to adapt the general language representations toward the intent classification objective. The training configuration 
was as follows: AdamW optimizer with a learning rate of 2e-5 and weight decay of 0.01 to prevent overfitting, a per-device batch size 
of 16, a maximum of 5 training epochs, and early stopping with a patience of 2 epochs monitoring validation macro-F1 to halt training 
when performance stopped improving. Input utterances were tokenized using the DistilBERT WordPiece tokenizer with a maximum 
sequence length of 128 tokens, with padding and truncation applied as needed. At the end of each epoch, the model was evaluated 
on the validation split, and the checkpoint with the highest validation macro-F1 was automatically saved. The best checkpoint was 
loaded at the end of training and saved to experiments/results/fine_tuned_model/ for inference. Training metrics including loss, 
accuracy, and macro-F1 were logged per epoch via TensorBoard. 
 
CNN Component: TextCNN Ablation Study  
The CNN component follows the TextCNN architecture, which applies parallel convolutional filters of varying sizes directly over word 
embedding matrices to capture local phrase-level patterns of different lengths. Unlike recurrent models that process sequences step

by step, convolutional filters slide across the embedding matrix simultaneously, making TextCNN computationally efficient. Word 
representations were initialized using pre-trained GloVe embeddings trained on 6 billion tokens with a vocabulary of 400,000 words 
and a dimensionality of 300. Words not found in the GloVe vocabulary were initialized as zero vectors. To satisfy the ablation 
requirement, four configurations were trained and compared. The first two ablations varied the embedding mode: in the static 
configuration, GloVe embedding weights were frozen during training so the model only learns the convolutional and classification 
layers; in the fine-tuned configuration, the embedding weights were also updated during backpropagation, allowing the model to 
adapt word representations to the specific vocabulary of the dataset. The second two ablations varied the convolutional filter sizes: 
configurations using filter sizes [2,3,4] capture bigram, trigram, and 4-gram patterns, while configurations using [3,4,5] capture 
trigram, 4-gram, and 5-gram patterns, with the latter designed to capture slightly longer local phrases. All four configurations used 50 
filters per size, a dropout rate of 0.5 applied before the final classification layer, Adam optimizer with a learning rate of 0.001, a batch 
size of 16, a maximum of 50 training epochs, and early stopping with a patience of 2 epochs based on validation macro-F1. The best 
model checkpoint across all configurations was saved to cnn_snapshot/ using PyTorch's torch.save(). The best performing 
configuration was static_3_4_5, which achieved a macro-F1 of 0.9859 on the test set. 
 
RL Component: LinUCB Contextual Bandit  
The RL component is a LinUCB (Linear Upper Confidence Bound) contextual bandit algorithm, which balances exploration and 
exploitation by selecting the action with the highest upper confidence bound estimate given the current context. In the context of 
this project, each interaction with the chatbot is treated as one episode: the agent observes a context vector, selects a response 
action, and receives a reward. The context vector is constructed by concatenating the 768-dimensional DistilBERT CLS token 
embedding  which encodes the semantic content of the input utterance , with the classifier's softmax confidence score, resulting in a 
769-dimensional context vector. The action space consists of 27 discrete actions, one for each intent category, where each action 
maps to a set of pre-written template responses stored in responses.py. The reward function is binary: +1 if the selected action 
matches the true intent label and 0 otherwise. The exploration-exploitation trade-off is controlled by the alpha parameter (set to 
1.5), where higher alpha values encourage more exploration. A confidence threshold of 0.70 is applied: if DistilBERT's softmax 
confidence for its top prediction exceeds 0.70, the agent trusts the NLP prediction directly without invoking the bandit's exploration 
mechanism; only when confidence falls below 0.70 does the agent use LinUCB's upper confidence bound calculation to select an 
action. The agent's internal parameter matrices (A and b per action) are updated after each interaction using the context vector and 
received reward, allowing the agent to refine its action-selection policy over time. The agent state is persisted between sessions via 
pickle serialization to experiments/results/linucb_agent.pkl.

Conclusion 
This project successfully designed, implemented, and evaluated a Customer Support Assistant for the e-commerce domain using the 
Bitext Customer Support LLM Chatbot Training Dataset. All three project objectives were met and exceeded. The DistilBERT intent 
classifier achieved a macro-F1 of 0.9967 and an accuracy of 0.9971 on the held-out test set, substantially exceeding the target 
threshold of 0.85. The TextCNN ablation study identified static_3_4_5 as the best CNN configuration with a macro-F1 of 0.9859, and 
interestingly found that static embeddings outperformed fine-tuned embeddings for filter sizes [3,4,5], suggesting that embedding 
fine-tuning does not consistently improve performance on clean synthetic data. The LinUCB RL agent demonstrated strong response 
selection performance in the offline simulation, with the confidence threshold mechanism functioning as intended by routing 
high-confidence predictions directly through the NLP model and reserving bandit exploration for uncertain cases.  
Key findings from the analysis include the following. First, the non-DL baseline (TF-IDF + Logistic Regression) performed strongly at 
0.9937 macro-F1, indicating that the synthetic dataset is relatively linearly separable and that the marginal performance gains from 
deep learning models reflect the ceiling imposed by the clean, structured nature of the data rather than a large modeling advantage. 
Second, DistilBERT's slice analysis showed that longer utterances (>8 words) are classified more reliably (0.9994 macro-F1) than 
shorter ones (0.9946), which is consistent with the expectation that transformers benefit from additional contextual tokens. Third, 
the identified failure cases are concentrated in semantically overlapping intent pairs such as cancel_order vs. change_order and 
set_up_shipping_address vs. change_shipping_address, indicating that lexical ambiguity between closely related intents is the 
primary challenge for this system.  
For future work, we  recommend to supplement the synthetic training data with real customer support conversations to improve 
robustness and reduce overconfident misclassifications, evaluate the system on out-of-scope queries to test rejection behavior, and 
implement an online learning loop for the RL agent so it can genuinely improve from live user feedback over time.
